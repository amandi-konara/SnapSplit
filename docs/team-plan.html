Group 51 · Mobile Application Development

SnapSplit Sprint Plan

Two weeks, four people, one working Android app. The plan aims at the proposal's MVP first (section 14.1): sign in, scan or upload, OCR, fix items, categorize, assign, calculate, save and view. Everything else is a bonus.

Mon 23 Nov – Sun 6 Dec 2026 Milestone 1 · Sun 29 Nov Feature freeze · Thu 3 Dec Submit · Sun 6 Dec

What to finish first

  1. Day 1: the shared foundation. Flutter project, folder layout, data models (money in whole cents), theme, router with placeholder screens and fake in-memory data. Nobody else is blocked after this.
  2. Week 1: the scan → summary flow working on a real phone, using in-memory data. This is the heart of the demo.
  3. Start of week 2: save to Supabase, then history and editing saved receipts.
  4. Last: Insights, Profile polish and extras. Testing and the report run from Thursday 3 Dec.
Who does what

Four tracks, each with its own folders

Each track owns separate files, so four people can push every day without merge conflicts. Decide together who takes which track.

How we work

Team rules

One branch per feature

Branch from main, open a pull request, and have one other member review it before merging.

15-minute check-in daily

What I finished, what I'm doing next, what's blocking me. A WhatsApp voice note works.

Changing a shared model?

Tell the group before merging. Models are the one place where everyone's code meets.

Test on a real Android phone

ML Kit and the camera don't work in Chrome or on Windows. Each member keeps a phone with USB debugging on.

Money is whole cents

Rs. 450.50 is stored as 45050. Never use double for money, so totals always add up.

Keys stay private

Supabase keys live in a git-ignored env/dev.json, shared in the group chat only.
